# Reference composition rules

Images in this folder are for human review only. Build variants from the
rules below. Never trace, import, or convert the images.

Source screenshots lived in `images/Screenshot …`. Renamed into `design/refs/<role>/`.
Notes were corrected for GRID / IMAGE / ROLE where the vision pass drifted.

**Mix:** 3 cover · 1 agenda · 1 problem · 1 solution · 2 how-it-works · 4 feature · 1 stats · 1 testimonial · 1 team · 4 closing

### Photo-footer family (shared base)

`problem-01`, `solution-01`, and `closing-01` are the **same photo-over-footer composition**. Build **one** shared layout family (`photo-footer`) with three role bindings — not three near-duplicate variants. Variant A for problem / solution / closing shares that base; differ only in footer height and copy density.

### Kit build priority

| Role | PRIMARY (build first) | Supporting / notes |
| --- | --- | --- |
| cover | cover-01, cover-02, cover-03 | cover-01/03: steal placement only — photo + treatment; no 3D, no shape-asset recreation |
| agenda | agenda-01 + variant B | |

| solution | solution-01 (= photo-footer A) + variant B | |
| how-it-works | how-it-works-01, how-it-works-02 | |
| feature | **feature-01, feature-02** | feature-03 / feature-04 supporting only |
| stats | stats-01 + variant B | |
| testimonial | testimonial-01 + variant B | |
| team | team-01 + variant B | |
| closing | **closing-01, closing-02** | closing-03 = panel idea reference only; closing-04 supporting. **Do not** build a resources/token-kit slide in v1 |

### Vibe / token awareness (do not “fix” the refs)

Fourteen of nineteen refs are `clean` vibe; most are shape- or frame-led, not photo-led. The kit will lean light and tidy for v1. Bold / dark / warm range must come from **palette** and **image-treatment** tokens: at least **two of six palettes are dark**, and **duotone** is one of the two treatments.
